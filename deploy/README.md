# Установка личного кабинета

## Установка на входной (relay) сервер — рекомендуемый вариант

Кабинет ставится на тот же сервер, где работает Xray-relay, и управляет им локально
(без SSH-паролей и ключей). Это один бинарник `/usr/local/bin/xray-panel` со встроенным интерфейсом,
systemd-сервис и база SQLite — ни Python, ни Node, ни Docker на сервере не нужны.

Сначала соберите бинарник на любой машине с Go 1.26+ и Node 22+:

```bash
make -C server web build SITE_NAME=example VERSION=v2.0.0
```

и скопируйте на сервер каталог `deploy/` и `server/dist/xray-panel-linux-amd64` (или `-arm64`),
сохранив пути относительно корня репозитория, либо укажите бинарник флагом `--binary`.

Требования: Xray и Caddy уже настроены скриптами `generate_config.sh` и `setup-caddy.sh`,
A-запись домена панели указывает на сервер.

```bash
# на сервере, из корня репозитория
sudo ./deploy/install_panel.sh \
  --panel-domain panel.example.com \
  --vpn-domain example.com \
  --admin-email admin@example.com \
  --site-name example
```

Повторный запуск того же скрипта — обновление (настройки и база сохраняются).

### Обновление одной командой

С машины разработчика кабинет обновляется командой

```bash
make -C server deploy VERSION=v2.8.0
```

Она собирает фронтенд и бинарник, копирует их на сервер, запускает `install_panel.sh` и проверяет,
что поднялась нужная версия и сайт отвечает. Настройки — в `deploy/deploy.env` (в git не попадает,
пример — `deploy/deploy.env.example`): адрес сервера, путь к SSH-ключу, домены и имя сайта.

Вход на серверы — только по SSH-ключу. Чтобы выключить вход по паролю, положите ключ в
`~/.ssh/authorized_keys` и создайте `/etc/ssh/sshd_config.d/00-keys-only.conf`:

```
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin prohibit-password
```

затем `sshd -t && systemctl reload ssh`. Файл с префиксом `00-` читается первым и перекрывает
настройки cloud-init. Перед перезагрузкой sshd проверьте вход по ключу во втором окне терминала.

Что получится:

- `https://panel.example.com` — личный кабинет; `https://example.com` — сайт-заглушка.
  Оба сайта слушают только `127.0.0.1:8444` и доступны снаружи через Xray REALITY на 443
  (реальный IP посетителя передаётся по PROXY protocol).
- Ключ = UUID во всех inbound: TCP 443, gRPC 8443, XHTTP 2053 (порт меняется `--xhttp-port`).
- Ключи добавляются и удаляются через API Xray (`127.0.0.1:10085`) без перезапуска —
  соединения других пользователей не рвутся. Конфиг сохраняется с проверкой `xray run -test`,
  резервные копии — `/var/lib/xray-panel/backups`.
- Блокировка пользователя сразу отключает его ключи, восстановление — возвращает.
- Трафик и онлайн по ключам собираются раз в 15 секунд, открытые страницы кабинета обновляются сами.
- Раз в минуту кабинет проверяет цепочку до интернета, канал до выходного сервера, Xray, сертификаты,
  диск и память; состояние видно на вкладке «Состояние» (/status), тревоги присылает Telegram-бот.
- Каждый день в 4:00 бот присылает администратору сжатую копию базы (`BACKUP_HOUR`), `/backup` — сразу.
- Подписки: тариф и срок «оплачено до» у пользователя; срок вышел — ключи отключаются до продления,
  ссылки не меняются.
- Почта (подтверждение адреса, «Забыли пароль?», смена адреса) — если в `panel.env` заданы `SMTP_HOST`,
  `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD` (в одинарных кавычках, если есть спецсимволы), `SMTP_FROM`;
  после правки — `systemctl restart xray-panel`.
- Настройки и секреты: `/etc/xray-panel/panel.env` (пароль первого администратора печатается
  при первой установке и лежит там же — смените его в разделе «Профиль»).
- Логи: `journalctl -u xray-panel`.

Уведомления о новых регистрациях с кнопками «Подтвердить»/«Отклонить» и тревоги мониторинга может
присылать Telegram-бот — см. разделы «Telegram-бот» и «Мониторинг» в
[`docs/WEB_CONTROL_PLANE.md`](../docs/WEB_CONTROL_PLANE.md).

Ключи, созданные раньше скриптами, подтягиваются кнопкой «Импортировать ключи с сервера».

## Обновление

Соберите новый бинарник и запустите тот же `install_panel.sh`: он заменит бинарник, применит миграции и
перезапустит сервис. Xray перезапускается, только если `bootstrap-xray` дописал в его конфиг что-то новое
(например, служебный вход `panel-probe` для мониторинга при первом обновлении до 2.3) — соединения при
этом переподключаются за пару секунд; в остальных случаях VPN-соединения не рвутся.
Прежняя Python-версия кабинета удаляется автоматически, её база и настройки подхватываются как есть.
